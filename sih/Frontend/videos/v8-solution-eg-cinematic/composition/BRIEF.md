## Notes — technical corrections, verified against the source

The storyboard is the user's; these details were checked against the codebase and corrected:

| Storyboard said | Source says | Used in v7 |
|---|---|---|
| ~15 rooms | Headline scenarios A/B use **16 bands** (`Backend/.../ScenarioLibrary.java`; explainer PDF: 16–32 bands by scenario) | **16 rooms** (4 floors × 4) → 16 bands |
| guard observes one room at a time | Receiver sees **K = 2 contiguous bands** per step (`ReceiverConfig.defaults()`: bandwidthK 2; `Receiver.java`: contiguous block, wraps) | guard's view covers **2 adjacent rooms**; 2 of 16 = 12.5 % visible |
| guard checks Room 01 → 02 → 03 … | Baseline = open-loop round-robin, stride = K, never uses feedback (`BaselineScheduler.java`) | view steps **01–02 → 03–04 → 05–06 …**, same route every time |
| looking at a room | 10 ms decision step, **3 ms retune dead time**, 4 ms minimum dwell (`ReceiverConfig.defaults()`) | beam blanks briefly on every move; small HUD spec line in the technical section |
| thief moves between rooms | emitter classes fixed / periodic / **agile** / random / **intermittent** (`EmitterBehavior.java`) | thief → unknown, frequency-agile emitter; flashlight → brief RF transmission |
| RF receiver | SIH26055: "Machine learning based **Electronic Support (ES) receiver** scheduler" | guard → ES receiver |
| signals appear while looking elsewhere | "Interception … is a two dimensional search problem … adjusting receiver's frequency at correct time"; "no prior reliable intelligence" | right band **and** right time; guard has no tip-off |

- No GHz axis: the 16-band scenarios are index-based (bands 0–15 in the app); no frequency span is
  claimed that the source does not state.
- Do NOT show the solution, a smarter guard, extra guards, AI/ML/DQN/RL, algorithms or
  optimization. The question is posed, never answered.
